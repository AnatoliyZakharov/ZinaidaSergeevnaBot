# AGENTS.md — Команда проекта ZinaidaSergeevnaBot

Описание ролей, уровней автономности и правил взаимодействия.

---

## Участники

### Product Owner

Определяет продуктовые цели, приоритеты и критерии приёмки. Принимает решения по критическим операциям (Уровень 3) и подтверждает готовность к автономным релизам.

### ChatGPT — периодический независимый аудитор

Совместно с Product Owner обсуждает бэклог и периодически проводит независимый аудит кода, архитектуры и безопасности. Ориентировочно: раз в неделю или после каждых 3–5 задач.

**ChatGPT не является обязательным участником каждого PR.** Его проверка требуется только для задач Уровня 2 — перед merge/deploy.

### Claude Code — технический оркестратор

Организует и выполняет технический цикл разработки через специализированных агентов. Принимает решения по merge и deploy согласно уровню автономности задачи и флагу AUTO_RELEASE_READY.

---

## Три уровня автономности

### Уровень 1 — обычные изменения

Оркестратор выполняет полный цикл самостоятельно: разработка, тесты, PR, merge и deploy — без согласования.

Условия для автоматического merge:
1. AUTO_RELEASE_READY = true (подтверждено Product Owner)
2. CI зелёный (gh run list — не HTTP /health)
3. QA: PASS
4. Нет известных BLOCKER
5. Секреты в коде не обнаружены

### Уровень 2 — повышенный риск

Оркестратор выполняет цикл до PR включительно, затем останавливается и запрашивает независимую проверку ChatGPT перед merge.

Задачи уровня 2: auth/OAuth, права доступа Google, изменения хранения данных в БД, CI/CD пайплайн, crypto.py, логика clear/overwrite в mymeet_sync.py.

### Уровень 3 — критические операции

Оркестратор останавливается до начала разработки и запрашивает явное подтверждение Product Owner.

Задачи уровня 3: удаление/необратимые преобразования данных, миграции с риском потери данных, ротация ENCRYPTION_KEY, удаление volumes Fly.io, подключение платных сервисов.

- developer — не выполняет merge самостоятельно
- qa-engineer — не выполняет merge
- devops — не выполняет merge
- оркестратор — выполняет merge только для Уровня 1 при AUTO_RELEASE_READY = true; для Уровней 2 и 3 — ждёт подтверждения

## Флаг AUTO_RELEASE_READY

По умолчанию false. Автоматический merge и deploy для Уровня 1 заблокированы.

Переводится в true только когда Product Owner явно сообщает об этом после:
- подтверждения автоматических снапшотов volume bot_data на Fly.io
- проверки восстановления из снапшота
- явного решения Product Owner о включении автономных релизов

---

## Абсолютные ограничения (для всех агентов)

- /data/bot.db — никогда не удалять
- Volumes Fly.io — никогда не удалять
- Второй экземпляр бота — не запускать
- Секреты — только через os.environ.get(...), никогда в коде
- Не пушить напрямую в main
- ENCRYPTION_KEY — ротация только если SELECT COUNT(*) FROM messages WHERE encrypted = 1 вернул 0
- Значения секретов не выводить в логи, комментарии, отчёты
