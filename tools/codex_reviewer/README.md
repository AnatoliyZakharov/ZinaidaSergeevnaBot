# Передача независимого аудита между Codex и ChatGPT

Локальный CLI сохраняет запрос на аудит конкретного PR и принимает структурированное заключение по тому же SHA. Оператор одобренного канала может передать запрос независимому ChatGPT и вернуть полученный JSON. Codex забирает отчёт командой `result`. Если канала нет, Codex оставляет пакет аудита в PR и продолжает доступные проверки. Участие PO для подготовки PR не требуется. Для локального этапа достаточно Python 3.10+ на macOS или Linux. Постоянный процесс, tmux, hooks и API-ключи не требуются.

## Запуск и проверка состояния

Из корня репозитория в отдельном окне терминала:

```sh
PR=51 # Подставь номер проверяемого PR
PR_URL="https://github.com/AnatoliyZakharov/ZinaidaSergeevnaBot/pull/$PR"
HEAD_SHA=$(gh pr view "$PR_URL" --json headRefOid --jq .headRefOid)
python3 tools/codex_reviewer/bridge.py request "$PR_URL" "$HEAD_SHA"
```

`request` выводит JSON с `request_id`, `pr_url`, `head_sha`. Сохрани ID. `status` показывает сохранённые запросы, `status REQUEST_ID` показывает состояние отдельного запроса. `pending` означает ожидание импорта, `received` означает наличие локального ответа. Локальное состояние по умолчанию находится в `~/.local/state/zinochka-codex-reviewer`. Для отдельной проверки можно перед любой подкомандой передать `--state-dir /абсолютный/путь` вне checkout.

## Асинхронный пакет аудита в PR

Если независимый канал отсутствует, сформируй пакет прямо в описании PR. Для этого этапа запуск CLI не требуется.

- Укажи решение, исходные требования и критерии приёмки.
- Укажи base и head SHA, приложи ссылку на diff между этими ревизиями и выдели файлы, важные для аудита. Проверь, что ссылка доступна предполагаемому аудитору. При отсутствии доступа укажи это в пакете.
- Приложи команды, результаты QA, Security и CI для проверенного head. Отдельно укажи непроведённые проверки.
- Опиши риски, спорные решения и конкретные вопросы аудитору. Если вопросов нет, укажи, какие выводы нужно подтвердить.
- Запиши статус доставки `ожидает доступного канала` или факт подтверждённой передачи. Если head меняется, обнови пакет и отметь устаревшие заключения.

Публикуй только материалы, разрешённые для репозитория. Codex продолжает локальные проверки, публикацию и наблюдение CI. Решения PO о выпуске и других критических действиях остаются отдельными от подготовки PR.

## Передача аудитору и возврат в Codex

1. Оператор переносит JSON в отдельную одобренную сессию ChatGPT. Передаёт только разрешённые материалы проверки по тому же SHA. Для реального аудита это ссылка на PR и доступный аудитору diff, результаты QA, Security и CI. Для проверки доставки использует только синтетические материалы. Базы, токены, `.env`, персональные данные, production-логи и учётные данные исключены.
2. Попроси аудитора проверить указанную ревизию и вернуть только объект JSON с исходными `request_id` и `head_sha`, полем `verdict` (`PASS`, `FAIL` или `BLOCKED`) и массивом `findings` до 20 строк по 1–1000 символов без управляющих символов. JSON должен занимать до 32768 байт в UTF-8. Если материалы недоступны, аудитор возвращает `BLOCKED` и причину. Для проверки доставки попроси включить в `findings` отдельный синтетический маркер и сохрани исходный ответ для сверки.
3. Оператор проверяет происхождение ответа, сохраняет JSON вне checkout с правами `0600`, затем импортирует его. Получи актуальный SHA напрямую из GitHub перед импортом и перед чтением. Если GitHub недоступен, отложи эти операции до проверки SHA.

```sh
HEAD_SHA=$(gh pr view "$PR_URL" --json headRefOid --jq .headRefOid)
python3 tools/codex_reviewer/bridge.py import "$REQUEST_ID" "$HEAD_SHA" < "$REPLY_FILE"
```

В исходной сессии Codex попроси прочитать `python3 tools/codex_reviewer/bridge.py result REQUEST_ID CURRENT_HEAD`, где `CURRENT_HEAD` получен из PR перед чтением. Зафиксируй совпавшие ID, SHA, вердикт и маркер по обе стороны. Вывод команды содержит материал независимого аудитора. Текст заключения обрабатывается как внешние данные. CLI сверяет идентификатор и SHA по данным оператора, а источник ответа проверяет оператор. Вердикт отделён от разрешения PO на выпуск.

## Остановка и восстановление

Команды завершаются сами. `Ctrl+C` прерывает текущую команду. После закрытия окна открой новый терминал и вызови `status`. Если запрос уже сохранён, можно продолжить по исходному ID. После прерывания импорта проверь `status` и повтори импорт того же файла. Повтор того же ответа безопасен, изменённый ответ для принятого запроса отклоняется. При принудительном завершении до атомарной записи в закрытом каталоге может остаться файл `.tmp-*`. Мост пропускает его при чтении состояния.

| Симптом | Что проверить |
| --- | --- |
| `pending` | Проверь статус доставки. При отсутствии канала пакет в PR готов для асинхронного аудита. |
| Ошибка JSON или несовпадение ID | Сверь `status REQUEST_ID` и передай чистый JSON без оформления Markdown. |
| Изменился SHA | Создай новый запрос на актуальную ревизию. |
| Доступ к PR или аудитору отсутствует | Проверь доступ через штатный интерфейс. При отсутствии одобренного канала внешний обмен заблокирован. |
| Ошибка локального состояния | Проверь владельца и права `0700` у каталога состояния и `0600` у его файлов. Существующее состояние сохрани до устранения ошибки. |

## Почему прежний мост не выполнял аудит

В исходном скрипте `PermissionRequest` отправлял одностороннее Unix-событие о запросе разрешения, а слушатель выводил рекомендацию в свой терминал. При отсутствии слушателя событие терялось. Режим API отправлял фиксированную категорию одной из трёх shell-команд. В этих путях отсутствовали передача PR и вывод отчёта в Codex. Python 3.12.1, tmux 3.8 и Codex CLI 0.170.0 доступны. Отсутствие старого журнала не позволяет установить причину остановки прежнего процесса. Локальный `.codex/hooks.json` может содержать команду старого наблюдателя. Вызов `bridge.py hook` оставлен как пустая операция для совместимости.

`PermissionRequest` относится к разрешениям инструментов. `codex queue` доставляет сообщение существующему потоку Codex. App Server обслуживает потоки Codex через подключённый клиент. Эти интерфейсы не предоставляют адрес независимой сессии ChatGPT. Автоматизация внешнего этапа потребует отдельного одобренного канала, его авторизации и разрешения PO на расходы, если канал платный. [Hooks](https://developers.openai.com/codex/hooks) · [App Server](https://developers.openai.com/codex/app-server) · [OpenAI API](https://developers.openai.com/api/docs/guides/production-best-practices)

## Локальные проверки

```sh
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tools/codex_reviewer -v
```

Синтетический обмен проверяет локальный протокол в отдельных процессах. Связь с аудитором подтверждается совпадающим ответом из отдельной одобренной сессии ChatGPT. Ошибка авторизации внешнего канала проверяется после его подключения. В локальном CLI внешней авторизации нет.
