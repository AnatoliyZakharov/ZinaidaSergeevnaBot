# Зинаида Сергеевна

«Зиночка» — Telegram-бот для работы со встречами и задачами. Он помогает планировать встречи в Google Календаре и добавлять ссылки Яндекс Телемоста, импортирует протоколы MYmeet в Google Таблицы и собирает на листе «Мои задачи» поручения из протоколов, Google Tasks и пересланных сообщений Telegram.

## Где искать код

| Компонент | Назначение |
| --- | --- |
| [`main.py`](main.py) | Точка входа, обработчики Telegram, работа с календарём и планировщик фоновых задач |
| [`mymeet_sync.py`](mymeet_sync.py) | Импорт протоколов MYmeet в Google Таблицы |
| [`my_tasks.py`](my_tasks.py), [`gtasks.py`](gtasks.py) | Обновление листа «Мои задачи» и операции с Google Tasks |
| [`auth.py`](auth.py) | Подключение аккаунта Google через OAuth и обработка ошибок Google API |
| [`db.py`](db.py), [`crypto.py`](crypto.py) | Хранение состояния в SQLite и шифрование отдельных полей |

## Разработка и тестирование

Используйте Python 3.11 и GNU Make. Установите зависимости из [`requirements.txt`](requirements.txt) в виртуальное окружение. Для полной проверки сценариев мониторинга установите также PyYAML, как в [GitHub CI](.github/workflows/smoke-tests.yml).

Из корня репозитория с активным виртуальным окружением выполните:

```sh
env -i PATH="$PATH" PYTHONDONTWRITEBYTECODE=1 make test
python3 ci/check_docker_packaging.py
```

Первая команда запускает [`test_smoke.py`](test_smoke.py) без переменных из текущего окружения. Вторая проверяет, что Dockerfile включает все локальные модули, нужные точке входа. Для этих проверок не нужны учётные данные или запущенный бот. GitHub CI дополнительно собирает образ и проверяет импорты внутри него.

Правила работы с репозиторием описаны в [AGENTS.md](AGENTS.md). Настройка интеграций и эксплуатация описаны в [руководстве администратора](docs/ADMIN.md).
